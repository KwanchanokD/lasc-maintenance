# ระบบดูแลครุภัณฑ์และเครื่องมือวิทยาศาสตร์ — PSU:LASC

ระบบทะเบียนครุภัณฑ์และเครื่องมือวิทยาศาสตร์ พร้อมบันทึกการ **บำรุงรักษา (PM)** **การสอบเทียบ (Calibration)**
และ **การซ่อมแซม** พร้อมระบบแจ้งเตือนกำหนดครั้งถัดไป — สำหรับ **เจ้าหน้าที่เท่านั้น** (ไม่มีหน้าสำหรับบุคคลภายนอก)
ของ **ศูนย์บริการสัตว์ทดลอง มหาวิทยาลัยสงขลานครินทร์**
(Laboratory Animals Service Center, Prince of Songkla University)

```
แอดมิน                                    เจ้าหน้าที่ (รวมแอดมิน)
  นำเข้า/เพิ่มครุภัณฑ์ + รูป + ผู้รับผิดชอบ ──►  บันทึก PM · สอบเทียบ · ซ่อมแซม ของครุภัณฑ์แต่ละชิ้น
                                              ◄── ระบบคำนวณวันครบกำหนดครั้งถัดไปให้อัตโนมัติ
                                              🔔 แจ้งเตือนเมื่อใกล้ครบกำหนด/เกินกำหนด (ในหน้าเว็บ + เดสก์ท็อป + อีเมล)
```

## บทบาทผู้ใช้

ระบบนี้ **ไม่มีการสมัครสมาชิกเอง** — ผู้ดูแลระบบต้องเพิ่มบัญชีเจ้าหน้าที่ทุกคนเองใน Firebase Console

| บทบาท | ค่าที่ตั้งใน `allowed/{uid}` | ทำอะไรได้ |
|---|---|---|
| **แอดมิน** | `"admin"` | เพิ่ม/แก้ไข/นำเข้า/เลิกใช้งานครุภัณฑ์ · แก้ค่าตั้งระบบ · บันทึกและยกเลิก PM/สอบเทียบ/ซ่อมได้ทุกรายการ |
| **เจ้าหน้าที่ทั่วไป** | `true` | ดูทะเบียนครุภัณฑ์ (แก้ไขไม่ได้) · บันทึก PM/สอบเทียบ/ซ่อมได้ทุกครุภัณฑ์ · ยกเลิกได้เฉพาะรายการที่ตนเองบันทึก |

## การตั้งค่า Firebase

ระบบใช้ **โปรเจกต์ Firebase ของตัวเอง** แยกจากระบบอื่นของศูนย์ฯ เพราะเป็นข้อมูลครุภัณฑ์/งบประมาณที่ต้องจำกัดวงผู้เข้าถึงเฉพาะเจ้าหน้าที่

### สร้างโปรเจกต์ (ทำครั้งเดียว ~10 นาที)

1. <https://console.firebase.google.com> → **Add project** → ตั้งชื่อ เช่น `psu-lasc-maintenance`
2. **Build → Realtime Database → Create Database** → เลือกตำแหน่ง **Singapore (asia-southeast1)** → *Start in locked mode*
3. **Build → Authentication → Get started → Sign-in method** → เปิด **Google** (และ/หรือ Email/Password ถ้าต้องการ)
4. **⚙ Project settings → General → Your apps** → กดไอคอน **`</>`** (Web) → ตั้งชื่อแอป → Register
5. คัดลอกค่าในกล่อง `firebaseConfig` มาวางแทนค่าว่างใน `index.html` ตรง `window.FIREBASE_CONFIG` (มีเครื่องหมาย ▼▼▼ กำกับไว้)
6. วางกฎความปลอดภัยตามหัวข้อถัดไป
7. เพิ่มบัญชีเจ้าหน้าที่คนแรกเป็น `"admin"` ตามหัวข้อ "เพิ่มสิทธิ์เจ้าหน้าที่"

> ถ้ายังไม่ได้วางค่า config หน้าเว็บจะขึ้นข้อความว่า “ระบบยังไม่ได้เชื่อมต่อฐานข้อมูล”

### โครงสร้างข้อมูล

```
data/asset/
  ├── equipment/{eqId}            ทะเบียนครุภัณฑ์ (รูปเก็บเป็น base64 บีบอัดแล้วในฟิลด์ photo)
  ├── pm/{eqId}/{pmId}             ประวัติการบำรุงรักษา
  ├── calibration/{eqId}/{calId}   ประวัติการสอบเทียบ
  ├── repair/{eqId}/{repId}        ประวัติการซ่อมแซม
  ├── incomingFaults/{id}          รายการแจ้งชำรุดที่รับมาจากระบบจองใช้เครื่องมือ (เขียนโดย apps-script-mailer.gs เท่านั้น)
  └── settings                     ค่าตั้งการแจ้งเตือน + Mailer URL
allowed/{uid}                      สิทธิ์เจ้าหน้าที่ ("admin" หรือ true)
```

### กฎความปลอดภัย

**ต้องวางกฎก่อนใช้งาน** — คัดลอกเนื้อหาทั้งหมดของ [`firebase-rules.json`](firebase-rules.json) ไปวางทับใน
Firebase Console → Realtime Database → **Rules** → **Publish**

หัวใจของกฎ:
- อ่านข้อมูลได้เฉพาะบัญชีที่อยู่ใน `allowed`
- แก้ไข/เพิ่ม/นำเข้าทะเบียนครุภัณฑ์ (`equipment`) ได้เฉพาะ `"admin"`
- บันทึก PM/สอบเทียบ/ซ่อมสร้างใหม่ได้ทุกบัญชีที่ได้รับสิทธิ์ · **แก้ไขรายการเดิม** (เช่น ยกเลิกรายการ) ได้เฉพาะ `"admin"` หรือผู้ที่บันทึกรายการนั้นเอง
- แก้ค่าตั้งระบบ (`settings`) ได้เฉพาะ `"admin"`
- ไม่มีใครดูรายชื่อ UID เจ้าหน้าที่ทั้งหมดได้จากหน้าเว็บ (อ่านได้เฉพาะของตัวเอง)

### เพิ่มสิทธิ์เจ้าหน้าที่

1. ให้เจ้าหน้าที่คนนั้น **เข้าสู่ระบบผ่านหน้าเว็บด้วย Google ก่อนอย่างน้อย 1 ครั้ง** (จะเห็นหน้า “ยังไม่มีสิทธิ์” พร้อม UID)
2. คัดลอก **UID** จากหน้านั้น (หรือจาก Firebase Console → Authentication → Users)
3. **Realtime Database → Data** → ที่ root กด **+** → Key: `allowed` → กด **+** ซ้อนเข้าไป →
   Key: *UID ที่คัดลอกมา* · Value: `"admin"` (แอดมิน) หรือ `true` (เจ้าหน้าที่ทั่วไป) → Add
4. ให้เจ้าหน้าที่ออกจากระบบแล้วเข้าใหม่ (หรือกด “ลองอีกครั้ง” ที่หน้า “ยังไม่มีสิทธิ์”)

ถอนสิทธิ์: ลบรายการ UID นั้นใต้ `allowed`

## เริ่มใช้งานครั้งแรก

1. สร้างโปรเจกต์ Firebase วางค่า config และวางกฎความปลอดภัย ตามหัวข้อด้านบน
2. เพิ่มตัวเองเป็น `"admin"` ใน `allowed` แล้วเข้าระบบ
3. แท็บ **⚙️ ตั้งค่าระบบ** → ตั้งชื่อหน่วยงาน จำนวนวันแจ้งเตือนล่วงหน้าของ PM และสอบเทียบ
4. แท็บ **🗄 ทะเบียนครุภัณฑ์** → กด **➕ เพิ่มครุภัณฑ์** ทีละชิ้น หรือ **📥 นำเข้าจาก Excel** ถ้ามีทะเบียนเดิมอยู่แล้ว
5. เพิ่มสิทธิ์เจ้าหน้าที่คนอื่น ๆ ตามหัวข้อ "เพิ่มสิทธิ์เจ้าหน้าที่"
6. (ไม่บังคับ) ตั้งค่าอีเมลแจ้งเตือนตาม [`apps-script-mailer.gs`](apps-script-mailer.gs)

## เชื่อมกับระบบจองใช้เครื่องมือวิทยาศาสตร์ (ไม่บังคับ)

เมื่อผู้ใช้บริการแจ้ง "เครื่องมือชำรุด" ในระบบจองใช้เครื่องมือ ([psu-lasc-equipment](https://kwanchanokd.github.io/psu-lasc-equipment/))
ระบบนั้นจะส่งข้อมูลมาที่ระบบนี้โดยอัตโนมัติ (ทางเดียว: จองฯ → ครุภัณฑ์ฯ) ให้ปรากฏในแท็บ "🔔 การแจ้งเตือน" ทันที
พร้อมอีเมลแจ้งผู้รับผิดชอบเครื่องมือ (ถ้าตั้งค่าอีเมลไว้ในทะเบียนครุภัณฑ์) — ไม่ต้องมีใครเปิดหน้าเว็บทั้งสองระบบพร้อมกัน

ทั้งสองระบบเป็นคนละโปรเจกต์ Firebase กัน จึงเชื่อมกันผ่าน **Apps Script ของระบบนี้** (`apps-script-mailer.gs`) แทนการเชื่อมฐานข้อมูลตรง ๆ
ไม่ต้องให้เจ้าหน้าที่มีบัญชีหรือสิทธิ์ในอีกระบบหนึ่งเพิ่ม

### วิธีตั้งค่า (ทำครั้งเดียว ~5 นาที)

1. เปิด [`apps-script-mailer.gs`](apps-script-mailer.gs) ของระบบนี้ → ตั้งค่า `DB_SECRET` (ดูวิธีขอค่านี้ในคอมเมนต์ท้ายไฟล์)
   และตั้ง `INBOUND_SECRET` เป็นข้อความสุ่มที่คาดเดายาก (เช่น สร้างจาก [1Password](https://1password.com/password-generator) หรือพิมพ์สุ่มเอง 20+ ตัวอักษร)
2. Deploy สคริปต์เป็น Web app ใหม่ (หรืออัปเดตเวอร์ชันของที่ deploy ไว้แล้ว) แล้วคัดลอก URL ที่ลงท้าย `/exec`
3. เปิดระบบจองใช้เครื่องมือ (`index.html` ของ psu-lasc-equipment) → แท็บ **⚙️ ตั้งค่าระบบ** → หัวข้อ "แจ้งเตือนไปยังระบบดูแลครุภัณฑ์และเครื่องมือวิทยาศาสตร์" →
   วาง URL จากข้อ 2 และรหัสลับเดียวกับ `INBOUND_SECRET` → บันทึกการตั้งค่า → กด "🛠 ทดสอบแจ้งไปยังระบบครุภัณฑ์" เพื่อตรวจว่าเชื่อมสำเร็จ
4. (แนะนำ) ในทะเบียนครุภัณฑ์ของระบบนี้ กรอก **"อีเมลผู้รับผิดชอบ"** ของแต่ละเครื่องมือให้ครบ เพื่อให้อีเมลแจ้งชำรุดส่งถึงคนที่ถูกต้องทันที

การจับคู่ครุภัณฑ์ระหว่างสองระบบใช้ **รหัสครุภัณฑ์ (code)** ตรงกันทุกตัวอักษร (ไม่สนตัวพิมพ์เล็ก/ใหญ่) —
ถ้ารหัสในระบบจองฯ ไม่ตรงกับทะเบียนของระบบนี้ รายการแจ้งเตือนจะยังปรากฏแต่ขึ้นข้อความ "ไม่พบครุภัณฑ์รหัสนี้ในทะเบียน"
ให้เจ้าหน้าที่กด "รับทราบ" แล้วตรวจสอบรหัสหรือเพิ่มครุภัณฑ์นั้นในทะเบียนก่อน

## ข้อจำกัดที่ควรทราบ

- **ต้องมีอินเทอร์เน็ตขณะบันทึก/อ่านข้อมูล** — ข้อมูลอยู่บนฐานข้อมูลกลาง จึงบันทึกแบบออฟไลน์ไม่ได้ (ข้อมูลที่โหลดไว้แล้วยังเปิดดูออฟไลน์ได้)
- **รูปประกอบ** บีบอัดและลดขนาดในเครื่องก่อนอัปโหลด (สูงสุด ~900px กว้าง คุณภาพ JPEG ~72%) เพื่อไม่ให้ฐานข้อมูลบวมเกินไป — ไม่เหมาะกับรูปที่ต้องการความละเอียดสูงมาก
- **วันครบกำหนดครั้งถัดไป** คำนวณจากบันทึก PM/สอบเทียบ**ล่าสุดที่ยังไม่ถูกยกเลิก**ของครุภัณฑ์นั้นเท่านั้น — ถ้ายังไม่เคยบันทึก PM/สอบเทียบเลย ระบบจะยังไม่ขึ้นแจ้งเตือนให้ (ต้องบันทึกครั้งแรกเองก่อน)
- **การส่งอีเมลแจ้งเตือนอัตโนมัติทุกวัน** (ไม่ต้องเปิดหน้าเว็บ) ต้องตั้งค่า Database secret และ Time-driven trigger ใน Apps Script เพิ่มเติมตามที่คอมเมนต์ไว้ใน `apps-script-mailer.gs` — ถ้าไม่ตั้งค่าส่วนนี้ ระบบยังแจ้งเตือนในหน้าเว็บ/เดสก์ท็อปได้ตามปกติ เพียงแต่ต้องกด "ส่งสรุปแจ้งเตือนตอนนี้" เองหรือมีคนเปิดหน้าเว็บ
- บัญชีที่มีสิทธิ์แก้ไขรายละเอียดคำขอ/บันทึกของตนเองในฐานข้อมูลได้ในทางเทคนิคก่อนกดบันทึก ซึ่งเพียงพอสำหรับการใช้งานภายในหน่วยงาน
